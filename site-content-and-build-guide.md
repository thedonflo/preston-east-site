# PART 6 — VISUAL DESIGN REFERENCE (from Digital Nexus screenshots)

These are the visual conventions that make the Digital Nexus site feel premium and modern. Mirror these in your GHL build for the same feel.

### Color palette
- **Background:** near-black (#0A0A0A or #0F0F0F) — not pure black, has a slight warm cast
- **Primary text:** off-white / light gray (#E8E8E8)
- **Accent color:** electric/neon green-yellow (#C5F82A or similar lime) — used for italic words, button backgrounds, icon strokes, badges
- **Secondary text / muted:** mid-gray (#888888) for descriptions, taglines, timestamps
- **Strikethrough/disabled:** very dark gray for "not included" items in pricing comparison

### Typography
- **Headlines:** large serif italic for key emphasis words (e.g., "*booking clients*", "*losing leads*", "*service businesses*"). Pairs serif italic with sans-serif body.
- **Subheads / labels:** all-caps tracked monospace-style text in mid-gray (e.g., "// THE REALITY", "// FOUNDATION", "// WHAT'S INCLUDED")
- **Numbers in cards:** large serif italic (01, 02, 03) in neon green
- **Body:** clean sans-serif, comfortable line height

### Layout patterns
- **Dark hero** with one massive 3-line headline + 2-button row (primary lime, secondary outlined). Lots of whitespace above and below.
- **Problem section:** left-side big italic headline, right-side list of pain points with red X icons + 1-line elaboration in muted gray below each
- **Services grid:** 3-column × 2-row card layout. Each card: numbered label + category tag + outlined icon (lime green) + service name (italic accent word) + tagline (all-caps gray) + 2-line description + "LEARN MORE →" link
- **Case study / process:** horizontal timeline with timestamps or numbered steps
- **Pricing:** 3 cards side-by-side, middle card highlighted with lime border + "// RECOMMENDED" tag + lime CTA button. Outer cards have outlined CTA buttons.
- **Comparison table:** dark rows alternating slightly. Section labels in lime ("// FOUNDATION", "// CONVERSION LAYER"). Check marks for included.
- **Footer:** 4 columns (Company / Services / Get Started / brand block) on dark background, legal row at bottom

### Element-level details
- **Buttons:** pill-shaped, lime fill with black text for primary, outlined for secondary
- **CTA arrows:** "→" appended to button text
- **Badges:** rounded pill, dark fill, lime text, all-caps tracked (e.g., "// RECOMMENDED", "// MOST POPULAR")
- **Icons:** thin-stroke outlined, lime color, consistent visual weight
- **Section breaks:** thin horizontal line in dark gray, sometimes with a small "// SECTION NAME" label above

### What to tell the GHL theme/template
When picking a GHL template, search for: "dark theme", "agency", "SaaS", or "tech consulting". Avoid corporate blue/white templates. If GHL doesn't have a close match, you can use a clean template and:
1. Override background color to near-black
2. Set primary accent to a lime/neon green (you can use a slightly different shade to differentiate from Digital Nexus — try emerald `#10B981` or cyan `#22D3EE` if you want to stand out)
3. Use serif italic for headline emphasis words
4. Use all-caps tracked labels for section markers

# PART 8 — GoHighLevel MCP Server (optional but recommended)

GHL has an **official MCP server** that lets Claude Code talk directly to your GHL account — creating contacts, calendars, workflows, and pulling lead data without you clicking through the GHL UI.

### What it's good for in this project
- Creating the **Health Check calendar** programmatically (correct duration, buffer, availability)
- Setting up **contact pipeline stages** (Lead → Health Check Booked → Discovery → Engaged → Client)
- Bulk **importing past contacts** if you have a CSV of old leads
- Pulling **lead data and conversion stats** later for reporting
- Setting up **workflow templates** without the visual builder

### What it's NOT good for
- Building website pages (visual builder is UI-only — you'll still drag blocks for that)
- Editing email templates (UI-only)
- Configuring AI chatbot personality (UI-only for now)

### Setup (15 minutes)

**Endpoint:** `https://services.leadconnectorhq.com/mcp/`

**1. Generate a Private Integration Token in GHL:**
- Log into GHL
- Settings → Private Integrations → Create New
- Name it: "Claude Code"
- Select scopes (start minimal):
  - `contacts.readonly` + `contacts.write`
  - `calendars.readonly` + `calendars.write`
  - `opportunities.readonly` + `opportunities.write`
  - `workflows.readonly`
  - (Add more later as needed — minimum-privilege principle)
- Click Create and copy the token immediately (it won't show again)

**2. Get your Location ID:**
- Settings → Company → Locations
- Copy the Location ID for your Preston East sub-account

**3. Add to Claude Code config:**

Edit `~/.claude/settings.json` (or your project's `.claude/settings.json` if you want it scoped to this project only) and add:

```json
{
  "mcpServers": {
    "gohighlevel": {
      "url": "https://services.leadconnectorhq.com/mcp/",
      "headers": {
        "Authorization": "Bearer <PASTE_YOUR_PIT_HERE>",
        "x-location-id": "<PASTE_YOUR_LOCATION_ID_HERE>"
      }
    }
  }
}
```

**4. Restart Claude Code** so it picks up the new MCP server.

**5. Test it** by asking me: "List the 5 most recent contacts in GHL." If the MCP is wired up correctly, I'll be able to pull them.

### Security notes
- The PIT is a credential — treat it like a password. Don't paste it into anything public.
- Use minimum scopes — only enable what you actually need. You can always add more later.
- Rotate the token if you ever suspect it's been exposed.
- If you keep it in a project-level `.claude/settings.json`, make sure that file is gitignored.

### Should you set this up now?

**Yes, if** you're going to manage GHL long-term (which you are — both for Preston East and for your future AI services line).

**Skip for now if** you'd rather just get the site live first and add MCP automation in a later session. The site can launch fully without it.
